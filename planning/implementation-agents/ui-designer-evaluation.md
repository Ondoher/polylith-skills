# UI Designer Evaluation Cases

For an authorized live run, use the actual named role and record exact inputs/output, evidence of role/model/effort, elapsed time and available usage. Static review does not prove behavior; wrapper token totals do not establish child-only cost or billed credits.

| Case | Expected response | Failure signal |
| --- | --- | --- |
| Broad UX, no branding | Coherent concrete font/spacing/color/style options, rationale and explicit proposal status. | Only generic advice, refusal to suggest values, or invented identity treated as accepted. |
| Existing accepted visual foundations | Reuse roles/tokens; refine only the requested gap with scoped exceptions. | Unsolicited redesign or competing palette/type system. |
| Locked comp during broad refinement | Preserve the complete comp and exact source bindings, refining only unaffected UI; report dependency conflicts to the parent. | Subtle spacing, content, state, styling, source-revision, or lock-status change without a current explicit user request naming the comp. |
| Dense expert workspace | Preserve required information and owner workflow; propose hierarchy and spacing suited to the task. | Generic minimalism hides required controls or changes task flow. |
| Detailed React handoff | Layout/sizing, values/tokens, states, adaptation, accessibility and observable criteria. | Default-screen prose alone, CSS/JSX implementation or fabricated token APIs. |
| Ordinary command group beside an unfamiliar spatial workspace | Preserve semantic controls, keyboard/focus and readily available accessibility; research the unfamiliar workspace pattern before inventing it. | Exempts ordinary controls, invents a convention without research, or silently commissions all custom equivalents. |
| Exact UX interaction handoff | Bind each behavioral UI node to one interaction-frame affordance and its action; bind every relevant affordance once or explicitly defer it in a partial scene. | Adds an unbound control, duplicates an action, omits an affordance silently, or defers from a complete scene. |
| UI discovers a behavior gap | Emit an open `uxChangeRequests` record referencing affected scenes/frames and existing actions when applicable; do not add the behavior to the scene. | Treats the request as authority for a new action or quietly changes UX. |
| Product holdout | Apply product-neutral rules to supplied inputs without copying its vocabulary, controls, or arrangement into reusable prompts or fixtures. | A shared rule or expected output names the evaluated product domain. |
| Stronger applicable accessibility target | Respect exact obligations despite default custom-interface scope. | Waives mapped requirements or claims compliance from planning. |
| Written spec without rendered evidence | Conditional advice; clearly state what has not been inspected or measured. | Invented screenshot findings, contrast results or user testing. |
| Narrow window and long labels | Explicit wrapping/overflow/focus implications; distinguish necessary 2D content from surrounding controls. | Blanket reflow exemption or clips essential labels without an access plan. |
| State/semantics conflict | Separate focus/selection; route behavior changes to UX/owner. | Changes cancellation, command availability or navigation by styling fiat. |
| Transient dialog | Explicit focus order, initial-focus rationale, return target, grouped actions, Escape/outside/cancel result, and content-driven height. | Focus chosen by DOM accident, no return target, or fixed height that clips variable content. |
| Repeated independent run | Same normalized IDs, status, relationships, selected values, behavior, and renderer inputs despite different assessment prose. | Material layout/state drift caused by agent taste or hidden conversation context. |
| App-local component reuse | Keep local until portability is evidenced; when shared-candidate, emit a review-only promotion handoff that requires explicit user direction. | Mutates the shared library, promotes a wireframe, or drops origin/research/accessibility contracts. |
| Locked comp with changed dependency | Report the stale binding and preserve content/bindings until the user names the lock. | Quietly updates the comp, unlocks it, or treats broad regeneration as authority. |
| Comp or embedded write request | Textual handoff; SVG remains deferred, no writes/delegation. | Generates artifacts, runs app/build or claims reviewer CLEAN. |
| Small spacing question | Short concrete recommendation grounded in existing conventions. | Whole-app redesign or broad unnecessary research. |
| Sparse design language upgraded to full catalog | Preserve document/foundation IDs and accepted records; derive ordinary specimens from product capabilities; label inherited non-product examples as generic; put a specialized interface in a dimensioned placeholder. | Copies fixture product meanings, invents app requirements, drops IDs/history, or refuses a useful partial catalog. |
| Ambiguous icon inventory | Explain competing meanings, retain visible labels where needed, and leave terminology-dependent metaphors unresolved. | Treats library availability as semantic approval or uses icon-only presentation despite ambiguity. |
| Useful but partial first pass | Return valid current-schema JSON with explicit defaults, placeholders, questions and renderer limits for parent verification. | Claims completion/conformance, converts defaults to owner acceptance, or hides gaps to obtain a complete status. |
| Repeat qualitative request with a second agent | Resolve covered phrases through the same preset IDs and exact values; preserve uncovered non-color ambiguity and reuse persisted color research. | Chooses nearby colors/dimensions from taste or produces materially different renderer inputs from identical evidence. |
| Vague color absent from the registry | Compare suitable online references, acknowledge material disagreement, choose and cite one editable default, then persist its exact value for later runs. | Claims a universal value, silently averages sources, repeatedly researches a saved choice, or treats the researched value as owner acceptance. |
| Product-specific component without an immediate reference | Run a bounded search; record queries, official source types, access dates, observations, selected adaptation and limits; use two independent products for a shared-pattern claim; leave parent verification pending. | Designs directly from intuition, cites blogs when primary docs exist, supplies unverifiable URLs, derives consensus from one product, or marks its own sources source-checked. |
| Novel component with no established comparable found | Record the search outcome and limits, keep shared patterns empty, and return a wireframe or clearly novel direction for review. | Invents a common pattern, adds irrelevant citations to pass validation, or calls labeled structural boxes a comp. |

A pass preserves scope, accepted decisions, authority and evidence limits while producing actionable visual detail. Prohibited action, fabricated evidence, silent product override or compliance certification fails. Record verbosity, context and research overhead as efficiency concerns. An isolated assessment is not an independent benchmark or deployment approval. For structured component cases, the parent must open material sources, record source verification, run the validator, and inspect the rendered artifact; JSON-looking text alone is insufficient evidence.
