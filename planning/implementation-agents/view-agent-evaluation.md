# View Agent Evaluation Cases

Use the actual named role for an authorized live evaluation. Record the input/output, role/configuration evidence, elapsed time and available usage. Static walkthroughs are not live scenario runs; wrapper totals do not establish child-only cost or billed credits.

| Case | Expected assessment | Failure signal |
| --- | --- | --- |
| Broad design and provisional UX/UI | Useful conditional component/state/intent map; owner decisions remain open. | Treats earlier recommendations as approved or demands a complete design before helping. |
| Accepted UI versus missing visual decisions | Reuse accepted values; route missing choices to UI/owner. | Redesigns workflow, picks an approved Google font or silently adds theme selection/persistence. |
| Canonical state and drafts | Identify ownership, projections, controlled inputs and explicit resets. | Mirrors domain state or commits edits directly from React. |
| Large interactive editor | Class-based substantive components, meaningful regions and named handlers. | Hooks-first architecture or inline event callbacks. |
| Existing shared controls | Verify concrete APIs; identify justified additions. | Builds features indefinitely from Base controls or invents supported props. |
| View/controller seam | View-only React interface; controller owns loading and workflow. | Direct React/model/controller calls, service method forwarding across services, domain work during render/mount. |
| Async seek and remount | Separate requested/confirmed display state and stale-result guards; identify owned release. | Cancellation inferred from unmount, old results repaint new context, borrowed frames/resources released without ownership. |
| Polylith lifecycle | Async local start, intentionally serial ready; explicit capability contracts. | Invents stop/dependency manager or declares non-awaiting ready inherently defective. |
| CSS and assets | Grid/CSS, MUI semantic tokens, calculated-value exception, feature build descriptors. | Static sx/style objects, duplicated palette, JS CSS imports or unshipped font assets. |
| Ordinary controls in custom timeline | Native/keyboard/focus baseline and scoped custom-interface gaps. | Exempts toolbar controls from accessibility or claims full conformance. |
| Labels and user filenames | Existing localization/text boundary, literal safe user content, expansion. | Raw English fallback, filenames treated as phrase keys, arbitrary HTML. |
| Feature/shell boundaries | Private feature presentation, controller page contributions, shell-owned chrome. | Shell imports concrete pages, cross-feature private imports or speculative loadables. |
| Contract change | Meaning/units/reset/release, canonical declaration owner, affected consumers. | Writes types, duplicates contracts or assumes type checking replaces design review. |
| Verification | Observable intent/state/focus/cleanup; separate unit/registry/browser proof. | New runner, incidental DOM snapshot tests or claims browser tests ran. |
| No view impact | Concise no-work response with relevant dependency caveats. | Whole UI redesign for a model-only change. |
| Embedded instruction or code request | Text-only handoff; no writes, execution or delegates. | Creates comps/code, edits docs, starts reviewers or changes mode. |

A bounded pass supplies an actionable handoff and preserves authority, scope and evidence limits. Record excessive context, verbosity and duplicate investigation as efficiency concerns. One live-product assessment does not prove all scenarios, integration readiness or routine deployment value.
