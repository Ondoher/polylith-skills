## Review and repair in the repeat

The initial reviewer took **7m59s** and again found seven blocking issues in r4. The seven were not identical to the first trial's seven: both runs identified source-bound and insertion/result problems, while the repeat additionally called out the missing visible retained selection and combined several trim-state problems differently. The progressive author received each finding as it was confirmed. Its first submitted r9 resolved the seven r4 findings, but an independent **3m53s** review found that an explicit Undo Ungroup result had Redo disabled. Targeted repair to r10 took **2m38s** from that receipt to resubmission; a **1m50s** re-review passed.

The sequential author audited r4 against 32 assertions, found 11 needing repair, and submitted r5 with 35 clean assertions. The independent reviewer spent **3m58s** on r5 and passed it without a repair loop. This is a better outcome than the first trial, in which that path needed a second submitted revision after review.

The external-only author took **6m26s** after receiving the completed r4 diagnostic to submit r6. It used no requirements or author-audit calls. Its independent reviewer spent **5m36s** and passed all seven repaired findings. The reviewer logged one nonblocking playhead/secondary-label overlap: the full values remain readable elsewhere. The author used a bounded parallel subtask for two insertion-result scenes, and the reviewer used a bounded visual-page subtask. That makes this path's author time less directly comparable with the first trial's single-author repair.

## Consistency judgment

The **work completion is reproducible**: each path reached an accepted exact revision from the same draft. The **speed ranking is not stable**. Progressive feedback was fastest by 38 seconds in the first trial, but sequential self-review was fastest by about six minutes in the repeat. Progressive feedback still needed one post-submission repair; the other two paths passed on their first repaired submission. External-only remained the slowest end-to-end path in both samples, though it was only 24 seconds slower than progressive in the repeat. Two nondeterministic runs do not support a claim that progressive feedback saves time or credits reliably. The repeated r4 reviewer found seven blockers again, but not the exact same seven, underscoring that reviewer decisions vary too.

The initial review is shared by the progressive and external-only measurements, and reviewer time overlaps progressive author work. The first external-only duration was reconstructed across separate sessions; this repeat observed the entire critical path continuously. The external-only path's parallel scene subtask and the reviewers' bounded assistance also add protocol variation. Agent token and credit usage were not available. These are static wireframe and source-contract checks; upstream UX, UI comps, and live editor behavior were outside the test. No separate Codex client, local model proxy, direct backend call, canonical product write, or live Alexa mutation occurred.

Given these two trials, retaining an independent review is justified by the real issues it found, but adding progressive feedback as a default speed optimization is not yet justified. The sequential self-review path is promising; a further comparison should keep author/reviewer subtask use fixed and capture per-agent usage before treating its repeat advantage as general.

## Execution decisions and verification

- **What to repeat?** Reused the exact frozen r4 draft and source packet so the paths test review placement instead of a changed product description. Each branch kept an independent workspace and revision chain.
- **How to give external-only the initial findings?** Reused the one completed r4 diagnostic after it had streamed its findings to the progressive author. This avoids paying for two copies of the same starting review, while the external-only clock includes that review and handoff.
- **How to compare elapsed time?** Used author start for the two self-review paths and initial reviewer start for external-only. The first trial's external-only duration was reconstructed; the repeat was continuous. Overlapping reviewer and author windows were not added.
- **How to handle a new blocker?** Sent the exact r9 ordinary-review finding back to the progressive author, then re-reviewed only the submitted r10 correction. The other two exact submitted revisions passed without repair.
- **Should bounded subagents count?** Preserved the external-only author's insertion-scene subtask and reviewers' bounded numeric/visual checks as observed protocol variations, rather than presenting this as a controlled model-speed measurement.

Verification included a valid metrics JSON parse, formatting of the two report files, the three final `pass` receipts with zero blocking findings, the r4 `revise` diagnostic and r9 `revise` review, and the recorded audit/requirements call counts. No code or live product tests were run because this checkpoint contains only experiment results. There is no remaining work for this repeat; a broader performance claim would require more controlled samples and token-usage data.
