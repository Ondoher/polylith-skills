# Seven runs of wireframe review placement

Five additional trials repeated the three-path experiment, giving seven runs from the same frozen Alexa-derived timeline wireframe revision 4 and source binding (`aebb31945ab696f0309be7db8aa96a2aebd6b29ddd8d1721e620284087d72c31`). Every path in every run reached an independent-review **pass**. [Machine-readable metrics](wireframe-review-seven-runs-20261001-metrics.json) retain exact seconds, UTC anchors, revision verdicts, and local helper timings. The [first](wireframe-review-overlap-comparison-20261001.md) and [second](wireframe-review-overlap-repeat-20261001.md) trial reports retain their original protocol notes.

**Paths.** Progressive means an initial reviewer sent individual revision-4 findings to a self-auditing author while both worked, followed by ordinary review of the submission. Self-review means the author worked without those findings, then received ordinary external review. External-only means the completed revision-4 diagnostic went to an author who repaired its findings without a requirements checklist or self-audit, followed by ordinary review. Each path's duration runs from its start to an accepted revision, including review and repair. The initial reviewer and progressive author overlap; that shared reviewer is included in the external-only critical path. These durations are alternatives, not stages to add.

The durations are rounded to the nearest second in the table; averages use unrounded recorded seconds. The seven-run mean difference between progressive and self-review is **3.059 seconds**, far below the variation between runs. The external-only mean is **3m18s slower than progressive**. Progressive was fastest in runs 1, 3, and 6; self-review in runs 2, 4, and 7; external-only in run 5. Ranges were 12m22s–35m02s, 14m13s–28m34s, and 18m21s–39m22s respectively. Seven nondeterministic runs do not establish a reliable speed winner between progressive and self-review.

Ordinary review rejected the first submitted repair in **5 of 7 progressive runs**, **4 of 7 self-review runs**, and **4 of 7 external-only runs**. All rejected branches passed after focused repair and re-review. The initial reviewer found anywhere from **4 to 13 blockers in the identical frozen draft**. Run 7's 13 findings and 14m14s diagnostic were the largest and drove its long progressive and external-only paths. This variability is substantive reviewer behavior, not a change to the input fixture. The recurring enabled Retry Add control during a known compatibility conflict was missed by self-review in runs 5–7 and caught by ordinary review; run 7 also exposed an unsupported saved-video crop entry. Progressive review found incomplete keyboard reorder destinations after submission; external-only review found selection scope, Undo label, and empty-selection command errors after its first repair.

For the five new runs, the mean interval from author start to first submission was **12m36s progressive** and **12m39s self-review**. Their mean first-submission-to-pass intervals, including ordinary review, any repair, and focused re-review, were **7m48s** and **8m55s**. The external-only author averaged **6m23s** from its post-diagnostic start to first submission, but its critical path also includes the initial diagnostic and handoff; its first-submission-to-pass interval averaged **7m51s**. These intervals are wall-clock windows, not isolated model reasoning or tool latency. Local helper execution was logged separately in the metrics and was small relative to the total windows; command preparation, model work, scheduling, rendering, and other activity remain mixed in the elapsed times. Agent token and credit usage were unavailable.

## Comparability and decisions

- **What input should be repeated?** Used the same frozen r4 artifact, UX packet, renderer, and source binding for all seven runs. Each new path had an isolated workspace. No product-description change, canonical artifact write, or live Alexa mutation occurred.
- **How should the paths overlap?** Started the progressive and blind self-review authors alongside one initial r4 reviewer in each new run. The reviewer streamed each confirmed finding to the progressive author; the external-only author started only after the completed diagnostic. A single diagnostic was reused for progressive and external-only within each run, avoiding a redundant initial review. New runs 3–7 were run sequentially to limit cross-run machine contention.
- **How should review failures count?** Continued each path through focused correction and an exact-revision independent pass. The table counts ordinary post-submission rejections; the required initial r4 diagnostic is shown separately. New runs 3–7 used fresh `gpt-6-astra/ultra` agents without delegated subtasks.
- **Which timestamps are comparable?** For runs 3–7, author-start and persisted pass receipts anchor progressive/self-review, and initial-review start and persisted pass receipt anchor external-only. Run 1's external-only total was reconstructed across sessions. Run 2 allowed bounded subtask work on the external-only path. Run 3 used its first recorded event for self-author start and an agent-reported initial-review start; a short external-author orientation preceded its start marker. In run 4 the progressive author sent an unsolicited status message to the initial reviewer, who reported that no author revision was inspected. These deviations are retained rather than hidden.
- **How were tool and permission errors handled?** Retried an authorized local browser capture after `spawn EPERM`, repaired mechanical duplicate-node or command errors in the affected branch, and kept the resulting elapsed time. No local model proxy, separate Codex client, or direct backend request was used.

The repeated experiment supports keeping independent review: it found concrete defects after every method's author work in multiple runs. It does **not** show that streaming reviewer findings consistently reduces turnaround or review failures. The next decision should use the observed failure patterns and perhaps a larger, product-independent fixture; this seven-run set alone is insufficient to set a default review-placement policy.

## Verification and retained evidence

All **21 path outcomes** have a final ordinary-review `pass` receipt with zero blockers. The metrics file was regenerated from saved event logs and the first two committed trial metrics; exact UTC anchors and each revision verdict are retained there. Isolated rendered artifacts, screenshots, receipts, and event logs for runs 3–7 remain under ignored `.codex-tmp/wireframe-seven-r*-20261001` directories for local inspection or replay. They are not canonical product data or part of the checkpoint. This experiment tested a static wireframe and its UX source contract; it did not review upstream UX approval, UI comps, application behavior, or a full refine-design run. No new unit tests were needed for this measurement-only report.
