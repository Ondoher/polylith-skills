# Alexa Video Editing — descriptive composition layout

## Scope and reading order

This layout covers the `video-workspace` authoring boundary and all 14 selected states in `scenarios.json`. It uses the shared `samples.json` fixture at the stated desktop viewport; names, frame numbers and media are fixture content. Stable IDs below name composition regions and components; source frame/action references are given in parentheses. The same editor structure persists behind contextual menus, dialogs and guards. A dialog is the active task layer while its captured editor remains visible and inert. UI chooses concrete dimensions and visual treatment from the supplied design language.

The normal reading and keyboard progression is **project header → workspace switcher → player and its inspection controls → noninteractive separator → video identity → composed-time row and its transport/precision tools → four aligned lanes → editing commands → contextual properties → local task status → application status**. The source's player-first rule applies within the active video surface; the project shell remains persistent above it. Contextual properties sit adjacent to the tracks where width permits and follow them in reading order. Neither property pane becomes a second editing mode. The composed-time row and lanes share one horizontal time window and retain their own vertical labels/controls when the timeline pans. A modal takes focus at its heading/subject, follows its listed input-to-action order, and returns to the invoking control or captured stopped editor context on dismissal.

### Growth and focus behavior

Keep the player above the separator and the time row directly aligned with all four lanes at the supplied desktop size. The tracks and ruler may scroll horizontally as one when zoomed; the header labels, lane mute and left Play/Stop remain reachable. If height is constrained, the editor content scrolls vertically as a coherent workspace while header/switcher and task status stay identifiable; dialogs scroll internally as needed, leaving their subject, validation and actions reachable. If width or translated labels grow, complete action groups wrap or move lower in the editor, and properties follow lanes in reading order; scope words such as “All tracks,” “output,” and “source” remain visible. Dialog fields and messages grow in their logical blocks. No phone behavior is proposed. Keyboard traversal follows region order, then active modal order, while pointer selection does not steal focus from an editing field. Focused range and trim handles have distinct boundary meaning; Escape cancels only the staged gesture or active dialog as applicable.

## Active-layer details and transitions

`MENU-SELECTION` is anchored to the selected range/object context and lists only applicable actions. A range exposes Delete, Split and Save Clip; whole objects expose Delete and Reorder; a single eligible named-clip copy exposes Update Named Clip; a single group shows Ungroup with explicit availability reason. It repeats scope before actions. A menu closes back to stopped editing, preserving selection and any prior failure context. (`selection-menu`, `selection-actions`, `dismiss-editor`)

`DIALOG-ADD` presents chooser, staged content identity/type, captured active track and insertion frame/edge or Append, duration and applicable crop summary before Add and Cancel. Choosing a file creates a whole-source unnamed occurrence; choosing a named clip copies its definition as an independent video-owned occurrence, grouped as one when composed; choosing a saved video expands its complete four-track description without a live nested reference. Valid Add pushes only colliding later occurrences on its destination track for single-track content and changes the draft atomically. While committing, retain staged choices and freeze competing edits. A failure returns to the same Add draft with actual local feedback and retry/Cancel; cancellation before commit inserts nothing. (`timeline-add`, `choose-timeline-content`, `insert-content`, `dismiss-editor`)

`DIALOG-TRACK-RECT` and `DIALOG-SOURCE-RECT` share `RECT-VISUAL`, `RECT-FIELDS`, `RECT-ACTIONS` but never share an ambiguous scope label. The former captures a track and output frame; the latter captures one occurrence or staged Add item and source frame. Each stops playback on opening and leaves it stopped on return. Visual handles and numeric Left/Top/Width/Height are equivalent; require positive dimensions and complete in-frame bounds. A field error grows beneath the affected input without dropping values or moving Apply into an ambiguous position. Full frame resets the **candidate** only. Existing-target Apply is one undoable draft edit; staged-Add source Apply only changes the pending Add choice. Cancel restores the captured original for that layer. Dialog focus order is subject, fields/visual adjustment, Full frame, Apply, Cancel; background commands cannot replace the captured target. (`track-rectangle`, `source-rectangle`, `video-framing-view`)

`DIALOG-CLIP-CREATE`, `DIALOG-CLIP-UPDATE`, `DIALOG-DRAFT-GUARD` and `DIALOG-PROJECT-GUARD` each place a concrete subject/consequence before their decisions. Their own validation or failure remains local and can grow vertically. Save/create/update commits freeze draft mutation until the actual result. The guard sequence has separate decision stages and retains the source editor behind it until continuation succeeds. Failure never silently dismisses a retryable dialog. (`clip-create`, `clip-update`, `video-guard`, `video-project-guard`)
