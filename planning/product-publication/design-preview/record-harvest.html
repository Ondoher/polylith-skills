1.2.1.1 Record a harvest

Use the Harvest entry form through six steps, including its confirmation dialog: set the date, enter a note, review, request a save, confirm, and receive the result.

Illustrative draftLocal use case · IO-01Requirements: REQ-01 (§5.1.1), REQ-02 (§5.1.2), REQ-03 (§5.1.3), REQ-04 (§6.1)
Who
A gardener recording a harvest
Starting condition
IO-01 has been opened from history using Record harvest
Successful outcome
A dated entry is saved and visible in history

The identified interaction object is IO-01 · Harvest entry form. Editing, review, and save-failure feedback share one draft. The form opens a supporting confirmation dialog during this use case; that dialog interaction is included in the same local case. This use case starts when the form is open and ends when it closes after success or cancellation. Harvest history is entry/exit context, not a second object whose tasks are covered here.

1.2.1.1.1 Main sequence

1

Set the harvest date

Gardener: accepts today's date or changes it in the open form.

System: starts with today's date and an empty note, retains the selected date in this draft, and shows Review entry and Cancel. No saved entry exists yet.

2

Add the observation and continue

Gardener: enters a note and selects Review entry. The date can still be changed here.

System: validates the note. If it is non-empty, the system carries both values into the form's review state. Editing or advancing to review does not save the entry.

If the note is empty: 2a · Stay in the form and correct it. To abandon the draft: 2b · Cancel the entry.

3

Review the entry before saving

Gardener: checks the date and full note in the review screen.

System: shows a read-only summary of the current draft, marks it as not saved, and offers Save entry, Edit details, and Cancel. Arriving here creates no history entry.

To correct either value: 3a · Return to details, then review again. To leave without saving: 2b · Cancel the same draft.

4

Request a save and open confirmation

Gardener: selects Save entry from the form's review state.

System: opens the Save this harvest? dialog above the form. The dialog repeats the current date and note and offers Save harvest or Back to review. The underlying draft remains intact; opening the dialog does not save it.

To reconsider: 4a · Close the dialog and return to review.

5

Confirm and save

Gardener: selects Save harvest in the confirmation dialog.

System: closes the dialog, validates the current draft, and attempts to persist the exact reviewed date and note. It reports no success until persistence completes. On success, continue to step 6.

If saving fails: 5a · Keep the draft and offer retry.

The saving-in-progress appearance and repeated-click behavior are unspecified in this example. No comp is supplied for that state; the confirmation comp above represents the moment before submission.

6

Receive confirmation and leave the form

Gardener: receives confirmation that the reviewed entry was saved.

System: closes IO-01 after success and returns to harvest history with Entry saved and the saved date and note. The entry remains available after closing and reopening the application.

1.2.1.1.2 Alternatives and recovery

Each branch begins at a named step and explains where the gardener ends up or rejoins the flow.

2a · Validation

The note is empty

At step 2, selecting Review entry with an empty or whitespace-only note keeps the gardener in the form. The system creates no entry, retains the date, and shows the note error. The gardener corrects the note at step 2, then selects Review entry again to reach step 3.

2b · Cancellation

Leave without saving

Cancel is available in the form and review screen before submission. Selecting it discards the same unsaved draft and returns to history. No entry is added. Starting again begins a new draft at step 1.

3a · Revision

Change the reviewed details

At step 3, the gardener selects Edit details. The system returns to the form with the date and note intact. The gardener updates either value at step 2 and selects Review entry again. The system validates the updated draft and rebuilds the summary at step 3. The earlier values are not saved and must not remain in the refreshed summary.

Visual return path: review screen → entry form with preserved values → review with the edits.

4a · Return from dialog

Return to review without saving

At step 4, the gardener selects Back to review. The system closes only the confirmation dialog, retains the entire draft, and rejoins step 3. Nothing is saved or discarded. From review, the gardener can edit details, request a save again, or cancel the whole draft.

5a · Recovery

The save does not succeed

If step 5 fails, the system keeps the reviewed date and note visible and explains the failure. Retry save submits that same reviewed draft and rejoins step 5 without reopening confirmation; success then continues to step 6. Edit details remains available to return to step 2 before reviewing and trying again. A failed attempt creates no saved entry and produces no success message.

1.2.1.1.3 End states

Path Where the gardener ends What persists
Save succeeds Harvest history with confirmation The saved entry, including after reopening
Cancel Harvest history without a new entry No draft from this attempt
Back to review from dialog The form's review state The unchanged unsaved draft; only the dialog closes
Return to edit The form, followed by an updated review The same unsaved draft, including its edits
Validation failure The form, ready for note correction No new entry; the entered date remains
Save failure The review screen, ready for retry or editing No new entry; the reviewed date and note remain

1.2.1.1.4 Shared references and gaps

Fields, action styling, and representative feedback treatments are described in Design language (§7). Their use in this flow is explained above.

Not specified in this example

Keyboard focus transitions, assistive announcements, saving-in-progress appearance, repeated-click handling while saving, dialog dismissal by Escape or backdrop, and behavior after closing an unsaved draft need their own source decisions. The visible examples do not imply that those states are designed.
